# Subscription groundwork

RevenueCat iOS SDK 5.94.0 and RevenueCatUI are pinned through purchases-ios-spm in XcodeGen. The configured Test Store integration, cybrguard_pro entitlement, Paywall and Customer Center are documented in [REVENUECAT_SWIFTUI.md](REVENUECAT_SWIFTUI.md). The plain subscription screen loads the current RevenueCat offering, uses the store-localised title/price and subscription period, supports purchase/restore, links to Apple subscription management and shows renewal/deletion disclosures plus privacy/terms notices. Sign-in and free access remain independent of payment. RevenueCat Test Store and server v2 verification are connected; Apple enrollment and production store configuration remain pending. No live subscription sale is claimed.

## Trust and lifecycle

The RevenueCat App User ID is the backend account UUID, never an email address or a client-selected user ID. The app configures/logs in to that identity after CybrGuard authentication. Purchase/restore completion calls authenticated `POST /v1/billing/reconcile`; only the server can update premium access. Purchase buttons also require the backend billing configuration to be available. SDK customer flags do not grant access.

The current project uses a modern v2 secret and `/v2/projects/{project}/customers/{account UUID}/active_entitlements` with a trusted internal Pro entitlement ID. Legacy deployments can still use v1 subscriber snapshots. Both use server-only credentials. It maps active `monitoring_family` to quota 15, otherwise active `cybrguard_pro` (or legacy `monitoring_personal`) to quota 3, otherwise free quota 1. Grace-period expiry can extend an expired entitlement. Missing/invalid recurring-subscription expiry cannot grant perpetual access. Cancellation normally retains access until confirmed expiry; refunds, expiration and transfers are determined from the latest subscriber snapshot, not the webhook's claimed expiry.

`premium_entitlements` access expires at the earlier of confirmed expiry and 24 hours since verification. Cron rechecks billing snapshots after six hours, before monitoring dispatch. Failed provider calls preserve the previous confirmed snapshot; after the freshness limit access expires until confirmation resumes. Per-account leases serialise reconciliation. Account deletion cascades billing state and conditional writes cannot recreate it. Plan downgrades retain addresses and pause those outside quota in primary-first order.

`POST /v1/billing/revenuecat/webhook` requires the exact configured Authorization header, a matching RevenueCat app ID and SANDBOX store events while production is blocked. Event IDs are recorded only after successful reconciliation; duplicate completed deliveries return 200. A failed lookup returns an error for RevenueCat retry. Delayed events use a fresh subscriber lookup; TRANSFER reconciles both existing UUID accounts. Unknown/deleted IDs never create users. Minimal processed event IDs are retained for 30 days; no raw event or customer payload is stored/logged. The implementation follows RevenueCat's supported [Authorization header and subscriber reconciliation guidance](https://www.revenuecat.com/docs/integrations/webhooks).

## Configure when accounts are ready

1. Complete Apple Developer enrollment. Register bundle `app.cybrguard`, set the signing team in ignored `apps/ios/Config/Local.xcconfig`, enable In-App Purchase and create the app in App Store Connect. Complete Apple's agreements, tax and banking setup before selling.
2. Create one subscription group with proposed product IDs `weekly`, `monthly`, `yearly`. Prices in the local StoreKit file are fictional test fixtures, not live advertised prices. Current RevenueCat Test Store prices are recorded separately in REVENUECAT_SWIFTUI.md. Configure actual regional prices and an optional eligible seven-day Personal introductory trial in App Store Connect.
3. Create a RevenueCat project and Apple app, connect App Store Connect and import those products. Attach weekly/monthly/yearly products to `cybrguard_pro`. Legacy Personal/Family entitlement mappings remain supported for previous configurations. Add packages to a current offering; use different offerings for weekly/monthly experiments. Set restore behaviour to keep purchases with the original App User ID unless an intentional transfer policy is reviewed and tested.
4. Put the public Apple SDK key (`appl_...`) in ignored `apps/ios/Config/Local.xcconfig` as `REVENUECAT_PUBLIC_KEY`. This public client key is distinct from server secrets. Configure equivalent release build settings through your secure build configuration.
5. Add `REVENUECAT_SECRET_KEY`, `REVENUECAT_APP_ID` and `REVENUECAT_WEBHOOK_AUTH` to local `.env`; the latter is a full unpredictable Authorization header value of at least 32 characters, for example `Bearer <random token>`. Keep secrets in ignored files. Copy runtime values to ignored `apps/api/.dev.vars` for local provider tests. `npm run deploy:staging` preserves/uploads these optional bindings when present; missing keys leave billing unavailable without blocking free scans.
6. Register `https://api.cybrguard.app/v1/billing/revenuecat/webhook` in RevenueCat with the exact Authorization value, scoped to the configured Apple app and SANDBOX. Production purchases are deliberately rejected until production rollout is implemented. Do not point RevenueCat at localhost.
7. Test Apple sandbox purchase, trial eligibility/renewal, restore after reinstall, cancellation, expiry, refund, billing failure/grace period, Family downgrade, duplicate/delayed webhooks and purchase transfer. Check server tier/quota and paused extra addresses, not just the SDK's displayed status. Remove the staging `STAGING_PREMIUM_EMAILS` test override when testing purchase expiry/refund enforcement; that independent administrative override deliberately grants test access. These live sandbox checks require completed enrollment and provider configuration and remain manual release gates.

## Local StoreKit verification

`apps/ios/Config/Subscriptions.storekit` contains three explicitly local test products and a seven-day introductory trial. It is a test-target resource and is not shipped in the app bundle. The simulator test `localStoreKitCataloguePurchaseAndExpiry` loads the actual StoreKit catalogue, purchases a verified Xcode transaction through Apple's `SKTestSession.buyProduct` API, finishes it and expires the subscription. This avoids signing into an Apple account during local automation. The test does not grant backend premium or pretend RevenueCat received an App Store receipt. Backend lifecycle tests use clearly fictional offline RevenueCat snapshots.

Run `npm run ios:generate`, then `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer xcodebuild -project apps/ios/Exposure.xcodeproj -scheme Exposure -destination 'platform=iOS Simulator,name=iPhone 18 Pro' test`. Tests use the app host because StoreKit's local service needs an application identity. For interactive local StoreKit testing, choose `Config/Subscriptions.storekit` under the scheme's Run Options in Xcode; account-connected RevenueCat testing still needs its configured project/public key and the documented RevenueCat local StoreKit setup. Do not interpret local test receipts as paid staging access.

Privacy policy and terms remain clearly labelled development notices requiring legal review. Push delivery is still unavailable. No Stripe checkout is included.
